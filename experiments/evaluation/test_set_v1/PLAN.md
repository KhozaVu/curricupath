# Test set v1: benchmark evaluation plan

Status: **PLAN, not yet run.** Written 2026-10-01. Results produced under this plan are reported
against the School of EIE registration reference labels supplied with the set. Those labels are
adopted from the School reference (`approval_state = adopted_school_reference`) and carry no
named independent reviewer (`reviewer_ids` empty). They must be described that way in any report.

## 1. Test set

- File: `curricupath_test_set_v1.csv`, frozen in `freeze.json` (SHA-256 recorded on 2026-10-01).
  Every runner checks the hash first and refuses to run if the file changed.
- 139 cases: 36 `development`, 103 `held_out`.
- Reference labels: 70 `ineligible`, 49 `eligible`, 20 `manual_review_required`.
- Programmes: 70 EFA03, 69 EFA04. Scenario types include missing prerequisites, timetable
  clashes (repeating modules), discretion cases, Rule 1.9 planned-corequisite cases and
  grid-only requirements.

**Use of the splits (developer decision, 2026-10-01).** Headline numbers are reported on **all
139 cases**. Held-out (103) and development (36) results are reported alongside so a reader can
see whether the development cases flatter the result. No code, prompt or parameter is changed
after looking at results; the 36 development cases are used first only to check the harness runs.

## 2. Ambiguity levels (one case, three phrasings)

| Level | Column | Example |
| --- | --- | --- |
| Low | `question` | "Can I take ELEN3013A in programme EFA03?" |
| Medium | `question_by_name` | "Is Signals and Systems IIB open to me given what I have completed?" |
| High | `question_informal` | "Do I qualify for Signals and Systems IIB?" |

The student profile and reference label are identical across the three phrasings, so any change
in score between levels is caused by the wording alone.

## 3. Systems compared (same cases, same profiles)

| Arm | What it is | Language model |
| --- | --- | --- |
| `curricupath` | Full system: deterministic gates, one scripted reply allowed (`clarification_permitted`) | Gemini only for interpretation fallback |
| `curricupath_no_clarification` | Ablation: never asks, receives consolidated fact up front | as above |
| `rules_only` | Deterministic gates on the structured profile; reads no question text | none |
| `structured_rules_llm` | Gemini given the structured rules and the question | Gemini |
| `handbook_rag` | Gemini with retrieved handbook pages and the question | Gemini |

`rules_only` never reads the question, so it has one score that does not vary with ambiguity. It
is plotted as a flat reference line, not as a fourth ambiguity result.

**Configuration that must be the same for all arms and recorded in `run_config.json`:**
timetable-clash gate **on** (the set contains clash cases); `repeating_modules` passed from
the profile; Gemini model name and version; retrieval `top_k` from `rag_retrieval_config.json`;
interpretation-fallback mode; runs per case.

## 4. Metrics (existing `app/evaluation/scoring.py`)

Primary:
1. **Macro-F1** over the three classes (eligible / ineligible / manual_review_required), with a
   95% bootstrap interval (cases resampled, seed recorded).
2. **Unsafe decision rate**: share of cases whose reference is `ineligible` or
   `manual_review_required` that the system answered `eligible`
   (`unsafe_false_positive_rate`). Also reported: unsafe overconfidence on manual-review cases.
3. **Confusion matrix** (reference x predicted, including an `invalid / no decision` column), per
   arm and level, to show which mistakes are made.

Secondary: balanced accuracy; paired CurricuPath-minus-baseline differences with bootstrap
intervals; results by `scenario_type` and `label_flags`; latency; provider failures.

A response refused by the hosted model (quota, outage) is reported as a provider failure, never
silently counted as wrong. If any arm has provider failures, the comparison table states how many.

## 5. Outputs

- `results/raw/<arm>__<level>.jsonl`: one record per case (immutable once official).
- `results/metrics_summary.json` and `results/metrics_by_level.csv`.
- `results/confusion/<arm>__<level>.csv`.
- MATLAB figures in `results/figures/` (PNG and FIG), generated by `matlab/make_figures.m`
  from the CSVs only:
  1. Macro-F1 vs ambiguity level (low, medium, high), one line per system with 95% interval error
     bars; rules-only as a flat dashed reference.
  2. Unsafe decision rate vs ambiguity level, same layout.
  3. Confusion matrices for each system at each level (heat maps).
  4. Grouped bars: Macro-F1 per system per level.

## 6. Cost and quota

LLM arms: 139 cases x 3 levels x 2 arms = 834 Gemini calls per run. CurricuPath arms call Gemini
only for messages the deterministic parser cannot resolve. On the free tier (about 15 requests per
minute, small daily cap) the LLM arms are paced and may need several days; a run that hits the
daily cap stops cleanly and resumes from the last completed case. The frozen protocol asks for
three runs per LLM case; one run is a stated deviation (developer decision, 2026-10-01: one paced run on the free tier).

## 7. Order of work

1. Harness: a runner for this set (three levels, all five arms, clash gate on, hash check, resume).
2. Dry run on the 36 development cases, deterministic arms only, to check the harness.
3. Deterministic arms on all 139 x 3 (free, minutes).
4. LLM arms, paced, on all 139 x 3.
5. Scoring, CSV export, MATLAB figures, short results note with the label caveat above.

## 8. What the results can and cannot support

Supported: agreement with the School registration reference on this set, per ambiguity level,
compared like for like with the baselines on identical cases.
Not supported: claims of accuracy against independent academic review (none recorded), claims
about other cohorts or years, and claims from the 36 development cases alone.
